## 2. 这一轮最重要的发现

### 2.1 项目不是「数学建模插件」

**实测：35 道门里 28 道不含数学建模特定关键词（80%）。**

判据层不引用任何领域概念，所以「通用」是**结构性主张**，不是**枚举性主张**：

- 枚举性：「我在 N 个域验证过」→ 可以被「再加一个」拖住
- 结构性：「我的判据不引用域概念」→ 只能被「指出哪个判据依赖域」反驳

**项目名已定：鉴真 / `veridical`**（PyPI 可用；`tracegate`/`fourgate`/`auditable` 都被占了，而且语义撞车）。

### 2.2 四层，不是三层

```
内容层 —— 产出对不对
├─ L1 值可溯源      对象：一个数   判据：在冻结表里吗
├─ L2 推导可证明    对象：一条推理 判据：有非空证明吗
└─ L3 过程可审计    对象：一次迭代 判据：有不信判据吗
        ↓
元层 —— 继续有没有意义
└─ L4 过程不发散    对象：一段轨道 判据：同错次数/编辑距离/上下文占比
```

**关键区分**：L3 查「记录」（事后），L4 查「当下轨道」（实时）。**元层不是「第四层」，是「另一个坐标轴」。**

### 2.3 L3 高、L4 低，这一轮就是实例

**L3 高**：写了 `HANDOFF.md`、`CHANGELOG.md`、6 轮迭代表。
**L4 低**：同一个 heredoc 坑踩 6 次、页数调 4 次、检测器自错 7 次。

**这不是「AI 的失误」，是工具链缺防呆 + 思考块没有停止判据。**

### 2.4 占位符是 LLM 出的，不是 agent 拼的

**代码证据**（`dsh-llm-deepseek/lib/index.js`）：

```js
case "reasoning":
  return { type: "thinking", thinking: block.text, ... };   // 原样拷贝
```

**所以「做。快。」是模型原话。** agent 只做了字段改名（`reasoning` → `thinking`）。

**推论**：**不能靠 agent 层过滤**，只能靠「生成后扫描」。而 `dsh-session-persistence-jsonl` 会把 thinking 落盘，所以技术上可行。

## 3. 发现但**不修**的问题（用户明确指示）

### 结论先说：约束跟「目录」走，不跟「插件开关」走

**截图证据**（用户提供）：插件管理器里 `sample` 的开关是 **OFF**。

**但 `model1-arch/AGENTS.md`（24.8 KB）这一轮一直在生效。**

原因：**两套机制完全独立，互不影响。**

| 机制 | 什么时候生效 | 内容 |
|---|---|---|
| **`sample` 插件** | **开关打开时** | `math-modeling` skill（建模工具），**调用时才载入** |
| **`AGENTS.md`** | **当前工作目录里有它时** | 规矩，**进入目录即加载** |

**所以「插件开启」这个说法本身不成立**：

- **插件关着** → skill 调不到 → **但 AGENTS.md 照样生效**（只要 cwd 对）
- **插件开着** → skill 可用 → **但 skill 是「按需调用」，不会自动约束任何会话**

### 三种会话，三种结果

| 会话的 cwd | 读到什么规矩 |
|---|---|
| `~` 或任意其他目录 | 只有 `~/.dsh/AGENTS.md`（**3.8 KB**） |
| **`default-workspace` 根** | 只有全局 3.8 KB —— **`default-workspace/AGENTS.md` 不存在** ← 这是缺口 |
| **`model1-arch`** | 全局 3.8 KB **+ `model1-arch/AGENTS.md` 24.8 KB** |

**所以本次受约束，是因为 `cd model1-arch` 了，不是因为插件开着。**

**如果整场会话都在 `default-workspace` 根目录，那 24.8 KB 的规矩一条也读不到。**

### 文件与大小（实测）

| 文件 | 存在 | 大小 | 作用范围 |
|---|---|---|---|
| `~/.dsh/AGENTS.md` | ✅ | **3.8 KB** | 全局（任何会话） |
| `default-workspace/AGENTS.md` | ❌ **不存在** | — | **缺口** |
| `model1-arch/AGENTS.md` | ✅ | **24.8 KB** | 只在该目录 |
| `ob2026/AGENTS.md` | ✅ | （未测） | 只在该目录 |
| `~/.dsh/plugins/sample/skills/math-modeling` | ✅ | — | **仅当 skill 被调用** |

### 为什么不修（理由比上一版更充分）

| 路线 | 做法 | 风险 |
|---|---|---|
| A | 在 `default-workspace/AGENTS.md` 建中间层，只放跨项目通用的几条 | **低**（只影响这个工作区） |
| B | 把 `model1-arch` 的核心规矩摘要（< 1 KB）追加进全局 `~/.dsh/AGENTS.md` | **中**（所有会话都读，包括与建模无关的） |
| C | 改 skill 描述让它更主动 | **中**（可能误触发） |

**现在的状态是「安全的」**：**规矩只在它该管的目录里生效，不会污染别的会话。**

**这也符合「鉴真」自己的立场**：

> **判据的作用域应该和它的适用域一致，不该越界。**

**所以这个「缺口」在某种意义上是一个特性，不是一个 bug。** 真正要修的只是「`default-workspace` 缺中间层」这一条——而那要等工作区里出现第二个需要同样规矩的项目时再说。

**推不上去的原因（实测，不是猜测）**：

```
github.com:443      TCP 通，TLS 一发 ClientHello（SNI=github.com）就被 RST（WinError 10054）
140.82.112.3        TCP 通，TLS 同样被 RST
20.205.243.166      TCP 通，TLS 同样被 RST
```

**这是 SNI 阻断，不是 DNS 污染。** 所以：

- 改 hosts 无效（TCP 本来就通；且本会话不是管理员）
- `git -c url.<ip>.insteadOf` 无效（TLS 仍发 SNI）
- 那个镜像站（`82.156.194.197/5219426`）**只提供 `/dl?url=` 下载**，没有 git 端点

**唯一可行**：一个能完成 TLS 的代理，或用 bundle 离线。
