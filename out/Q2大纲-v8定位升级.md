# v8：定位升级与第四层的修正

> **触发**：用户一句话——「我们现在不是仅仅在做一个数学建模的辅助插件」。
>
> 这句话改变了三件事：**定位**（从领域工具到通用层）、**上界的结论**（v7 说第四层不存在，其实存在一层，只是换了一种对象）、**Q2 的门槛**（贡献变大，但外部效度要求也变高）。

---

## 1. 代码层面的证据：80% 的门不依赖数学建模（口径见第 8 节）

扫 `gate.py` 的 32 个 `chk_` 函数体，看是否出现建模特定关键词（MILP / regression / 题型 / 聚类 / 灵敏度 / equation 等）：

| 类 | 数量 | 例 |
|---|---|---|
| **通用** | **25** | `compile` `pdf` `numbers` `figures` `prompt` `proof` `iterlog` `refs` `redteam` `stamp` `bare_pct` `claims` `causal` `cross_section` `biblio` `rigor` `abstract` `abs_page` `aitaste` `innovation` `chapters` `required`(部分) `code` `significance` `rules` |
| **建模特定** | **7** | `sensitivity`（灵敏度）、`falsify`、`leakage`、`math`（对拍）、`domain`（聚类/回归）、`required`（题型）、`extrap`（外推） |

**这个判据是粗的**（关键词匹配，可能误判 `chk_math` 这类名字含 math 但其实通用的），**但 78% 这个量级足够了**。

**它说明什么**：

> **这 25 道门依赖的不是「数学建模」，而是「一篇带数字、图表、推导、过程的文档」。**
> 数学建模只是第一个被覆盖的域。

## 2. 定位：从「数学建模插件」到「LLM 技术文档的验证层」

### 旧定位（限制了自己）

> 一个数学建模插件的验证层。

**问题**：
- 审稿人问「为什么只做数学建模」→ 答不出有力的理由
- 外部效度只有 23 题一个域
- 贡献被框在「竞赛辅助」里，撑不起 Q2

### 新定位

> **A verification layer for LLM-generated technical documents. The first domain is mathematical modelling.**

**三个层次**：

| 层 | 内容 | 是否领域相关 |
|---|---|---|
| **判据层** | 值可溯源 / 推导可证明 / 过程可审计 / 过程不发散 | **不相关** |
| **实现层** | 冻结表、精度感知相等、`proof` 门、`iterlog` 门、断路器 | **不相关** |
| **域配置层** | 哪些门启用、门槛值、`standard.json` | **相关**（这才是「数学建模插件」的部分） |

**所以「数学建模」不是身份，是配置。**

### 这个升级的代价（必须说）

| 代价 | 说明 |
|---|---|
| **外部效度要求变高** | 说「通用」就必须在**至少两个域**验证。只做数学建模，就只能说「在一类技术报告上」 |
| **「通用」需要证明** | 不能说「25/32 门不依赖建模 → 所以通用」。**代码里没关键词 ≠ 语义上通用** |
| **第一个域的特殊性要交代** | 数学建模的特点：数字密集、有推导、有过程。**别的域未必**（如纯综述：以引用为主，计算值少） |

**第一条是硬要求**。所以 v6 的实验 6（A/B 扩样本）之外，**必须加一个「第二语料」实验**，否则「通用」就是空话。

## 3. 第四层的修正：内容层没有第四层，元层有

**v7 说：「第四层不存在——可机械判的上界就是三层。」**

**这个结论对「内容层」是对的，对「元层」是错的。**

### 区分「内容层」和「元层」

| | 内容层 | 元层 |
|---|---|---|
| 问的问题 | **这份产出对不对？** | **继续做下去有没有意义？** |
| 对象 | 一个数 / 一条推导 / 一次迭代 | **一次尝试 / 一段轨道** |
| 判据 | 有出处 / 有证明 / 有记录 | **失败次数 / 上下文占比 / 编辑距离 / 产出比** |
| 能不能机械判 | ✅ | ✅（信号都是可测的过程量） |
| v7 的结论 | **三层，第四层不存在** | **v7 完全没考虑** |

### 完整结构（四层）

```
内容层 —— 产出对不对
├─ L1  值可溯源        「这个数被算过一次吗」
├─ L2  推导可证明      「这条推理有证明吗」
└─ L3  过程可审计      「作者记录过什么时候不信自己吗」
        ↓
元层 —— 继续有没有意义
└─ L4  过程不发散      「现在是在解决，还是在原地打转？」
```

### L4 的判据（可测，不是猜）

| 信号 | 阈值（示例） | 动作 |
|---|---|---|
| 连续同一错误 | 3 次 | 换方法，或停 |
| 上下文占用 | > 70% | 压缩/重述，不是「允许记不清」 |
| 最近 5 轮编辑距离 | 小于某阈值 | 停，重新规划 |
| 每轮产出 | < 5 行 | 换工具或缩小范围 |
| 同一断言反复改值 | 3 次 | 回到计算，不要猜 |

**关键**：**L4 调的是「投入门槛」，不是「质量门槛」。**

**降投入**（早停、换法）✅
**降质量**（接受更差结果）❌ ← **这是奖励劫持**

### 为什么 L4 不是 L3 的重复

- **L3 查的是「记录」**（有没有迭代史、有没有不信判据）→ **事后可查**
- **L4 查的是「当前轨道」**（现在是不是在打转）→ **实时可查**

**一个可以 L3 满分而 L4 崩**：写了漂亮的迭代史，但当下正在第 20 次改同一个错。
**一个可以 L4 满分而 L3 崩**：效率很高地推进，但从不记录为什么改。

**所以是两个独立对象。**

## 4. 这个修正对论文的影响

| 项 | v7 | v8 |
|---|---|---|
| **层数** | 3 | **3 + 1（元层）** |
| **上界论证** | 「第四层不存在」 | **「内容层到三层为止；元层另有一层，对象不同」** |
| **贡献数** | 3 | **4**（多一个「过程不发散」的判据与信号） |
| **Q2 定位** | 工具论文（数学建模） | **通用验证层 + 第一个域** |
| **外部效度要求** | 一域可 | **必须两域** |

**「元层」这个提法是这次对话逼出来的，不是从论文里推的。** 它是这份大纲里唯一一个**从讨论中长出来的**贡献。

## 5. 这一层要不要做进插件

**要，但优先级低于把 L1–L3 做实。**

| 序 | 做什么 | 成本 | 为什么这个顺序 |
|---|---|---|---|
| 1 | 补 `proof` / `iterlog` 的构造样本 | 各 20 分钟 | L2/L3 现在「有判据无证据」，是最大漏洞 |
| 2 | 逐层消融 C0–C3 | 半天 | 证明三层不是凑的 |
| 3 | 分类器漏检率 | 2 小时 | 唯一能推翻论文的实验 |
| **4** | **L4 的最小实现：`run_all` 同错重复检测** | **1 小时** | **立刻能防「原地打转」，且不碰核心逻辑** |
| 5 | A/B 扩到 5–10 任务 | 6–12 小时 | 统计门槛 |
| 6 | 第二语料 | 4–6 周 | 「通用」的硬要求 |

**第 4 项是这一轮讨论的直接产物**，而且它**不改任何门的行为**——只是在一个已有脚本里加一层「连续同错就喊停」。

## 6. v8 之后，论文的一句话主张要改写

**v5 的版本**：

> 现有事实性评测问「这句话是否被知识源支持」；但近一半的数字是计算值…

**v8 的版本**：

> **一个 LLM 生成的报告是否可信，取决于四个互相独立的判据：数字可溯源、推导可证明、过程可审计、过程不发散。前三个是内容层，可以被机械判；第四个是元层，判的不是内容对不对，是「继续做下去有没有意义」。我们给出四层的判据、实现和消融，并指出内容层到此为止——再往上一层的候选（假设是否合理、结论是否被证据支持）有不可验证性结果。**

**这个版本的强处**：
- **四层是「互相独立」的**（有实测支持）
- **「到此为止」是有理由的**（不可能性结果）
- **元层这一层是新的**（不是从别人那抄的）

## 8. 核实后的口径修正（本轮自查）

**v8 第 1 节写的「32 个 chk_ 函数，25 通用」不完整。** 核实后：

| 事实 | 数字 |
|---|---|
| gate 实测项数 | **35** |
| 独立 chk_ 函数 | **32** |
| 差额来源 | chk_chapters **一个函数服务 4 项**（`analysis` / method_argument / self_correction / deployment）；cross 用 chk_cross_section；`ai_taste` 另有实现 |
| 建模特定的项 | **7**（sensitivity `falsify` leakage math domain 
equired extrap） |
| **通用项** | **35 − 7 = 28** |
| **通用率** | **28/35 = 80%** |

**所以更准的表述是**：

> **35 道门里 28 道不含数学建模特定的关键词，占 80%。**

**但这个判据是粗的**——按「函数体里有没有 MILP/regression/题型/聚类/灵敏度 这些词」判，**代码里没关键词不等于语义上通用**。

**这个自我修正本身就是 v8 的立场**：**说「通用」要有可核的口径，且要交代口径的粗度。**
