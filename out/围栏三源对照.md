# 围栏三源对照 · 本地 / purge / 学术界

> 用户指出：「对于围栏，你本身的围栏、还有 purge 的围栏、和 GitHub 上都可以找借鉴。
> 对于你建议的下一步，这些改好了都要成为约束的。」
>
> 本文是那次对照的结果。结论：**我从两个外部源各补了一门，而且补上的门立刻让两份论文都红了。**

---

## 一、三源各有什么

### 源 A · 本地 `model1-arch`（我这几轮建的）

| 门 | 判据 | 覆盖 |
|---|---|---|
| `numbers` | 小数 token 必须追到冻结表 | 数字溯源 |
| `refs` | `\ref` 配平 + `\cite` 非空 + **≥10 条文献** | 引用 |
| `figures` | 质量均分 + **≥6 张** | 图 |
| `sensitivity` | 敏感性词 + 参数范围 + 扰动后判断 | 参数敏感性 |
| `redteam` | 按 `\section` 数一板一角色 | 分板审核 |
| `stamp` | 判决绑定到文件摘要 | 防「改完还引用旧绿」 |
| `arch_invariants`（工具） | 12 条架构不变式 | 架构一致性 |
| `fence_mutation`（工具） | 改坏围栏看测试是否报错 | 围栏自身有效 |

### 源 B · `purge`（本机 dsh-purge）

它的围栏不是「论文质量」，是「对 harness 的 63 个补丁」：

| 可借鉴点 | 具体形态 |
|---|---|
| **逐项结构化状态** | 每个补丁有 **ID + 名称 + 分类 + 状态**（`✓ [#16] FS_FENCE_DISABLED 代码/Code — applied`） |
| **计数与缺口** | `61/63 applied, 0 pending` — 一句话给出总数/成功/待办 |
| **分类维度** | 提示词 / 代码 / 工具 / 版本兼容 —— 分类让「哪一类出了问题」一眼可见 |
| **审计流水** | `purge_audit` 记录每次破坏性操作（apply/revert/uninstall）的审批与结果 |
| **可回滚** | `purge_revert` 保留备份原件 |

**我借鉴了什么**：
- **计数 + 缺口**：`gate` 的「衰减项 16/19 通过 ← redteam, significance, biblio」直接点名**哪几项红**，不是只说「未通过」
- **分类**：`gate` 的「硬门 / 半衰项 / 衰减项 / 0 分项」是同一思路

**我没借鉴的**：**审计流水**。`purge` 每次破坏性操作都留一条可读记录；我的 `gate --stamp` 只存摘要，**不存「谁在什么时候改了什么」**。这是缺口。

### 源 C · 学术界（NeurIPS Paper Checklist）

**这是最权威的一源** —— 评审人**必须**按它打分（[NeurIPS 2024 官方论文里的完整清单](https://proceedings.neurips.cc/paper_files/paper/2024/file/e93ac11b7e96337962fa38b0460ede3b-Paper-Conference.pdf)，[OpenReview 说明](https://openreview.net/pdf?id=LrnZDU9g7N)）。

16 项里，与「论文质量门」直接对应的：

| NeurIPS 项 | 我的门 | 覆盖 |
|---|---|---|
| 1 Claims | `claims`（软） | ✅ |
| 2 Limitations | 无门，靠红队 conclusion 板 | ⚠️ 间接 |
| 3 Theory Assumptions and Proofs | 无门，靠红队 assumptions 板 | ⚠️ 间接 |
| 4 Experimental Result Reproducibility | `code` + `numbers` | ✅ |
| 5 Open Access to Data and Code | 只有 `nonresearch.json` 豁免，**没有「开放声明」检查** | ❌ |
| 6 Experimental Setting/Details | 部分（`timing`） | ⚠️ |
| **7 Experiment Statistical Significance** | **原来没有** → **本轮补 `significance`** | ✅ 新 |
| 8 Compute Resources | 部分 | ⚠️ |
| 16 Declaration of LLM Usage | `ai_taste` + 论文有专节 | ✅ |

**净结论：原来覆盖 8/16，本轮补到 9/16。**

## 二、本轮补的两门（都立刻见红）

### 新增 1 · `chk_sensitivity`（补「敏感性分析」这层分水岭）

三件同时成立才 PASS：① sensitivity/robustness 表述 ② 一个参数范围 ③ 扰动后的判断。

### 新增 2 · `chk_significance`（直接对应 NeurIPS 第 7 项）

要求：① 置信/区间/误差的表述 ② **一个具体区间或误差数值**。

**并排除平凡区间**：`[0,1]` 是份额的定义域，不是区间估计 —— 实测 `out/d2026c` 靠它蒙混过关。

**补完后的实测**：

```
checks 总数：30 → 32

out/final   [FAIL] significance  没有具体区间或误差数值
out/d2026c  [FAIL] significance  没有具体区间或误差数值
```

**两份论文都红。** 这不是巧合：`out/final` 的所有数字是点值（`96.9%`、`88.2%`），`out/d2026c` 的不确定性是「可行集宽度」（一种区间，但没写成区间形式）。

## 三、还差的三项（按 NeurIPS 清单）

| 缺口 | 现状 | 补法 |
|---|---|---|
| **第 5 项 · 数据与代码开放** | 只有「不投学术场合」的豁免文件，**没有正向声明** | 加 `chk_open`：要求论文写明数据/代码的获取方式（URL 或「不公开 + 理由」） |
| **第 6 项 · 实验设置细节** | 只有耗时表 | 加 `chk_setting`：要求写明超参数/随机种子/环境 |
| **审计流水**（借自 purge） | `gate --stamp` 只存摘要 | 每次 `--stamp` 追加一行 `{时间, 文件摘要, 判决, 红项}` 到 `out/final/gate_log.jsonl` |

## 四、「我建议的下一步」怎么变成约束

用户的原话：**「这些改好了都要成为约束的。」**

| 我原来的建议 | 现在的约束 |
|---|---|
| 补 8–12 条文献 | ✅ `chk_refs` 的 `min_bib = 10`，低于即 FAIL |
| 把 3 张表改成图 | ✅ `chk_figures` 的 `min_figs = 6`，低于即 FAIL |
| 摘要加「一击」 | ❌ 仍无法机械化（这是内容判断，不装门） |
| 修 2 个未溯源数 | ✅ `chk_numbers` 已覆盖（`single_point`） |
| 在论文里定位「partial identification」 | ✅ 已写进 `chk_significance` 的动机 |

**加不了的必须说清**：「摘要有一句能记住的话」「模型对不对」——这两件**没有机械判据**，只能靠红队与人读。装一道「关键词命中」的假门比不装更糟。

## 五、门槛值从哪来（都是设计选择，不是定理）

| 门槛 | 值 | 来历 | 可覆盖 |
|---|---|---|---|
| `min_bib` | 10 | 优秀论文经验区间 8–15 | `standard.json` |
| `min_figs` | 6 | 一等稿经验区间 6–10 | `standard.json` |
| 显著性区间 | 非平凡 | `[0,1]` 是定义域不是估计 | 代码内排除 |

**这三条都不是定理**，所以：① 写成常量可覆盖；② 结论行打印「实际值 / 门槛」；③ 只对 `deliverable: true` 的目录生效。
