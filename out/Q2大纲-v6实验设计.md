## 实验 1：`proof` 门的构造样本

**要判的事**：`proof` 门在「有命题、无证明」时会不会报错；把门改坏后它会不会漏。

### 构造（不到 5 分钟）

```powershell
# 1) 复制一份论文
New-Item -ItemType Directory -Force out/_probe/proof_nn
Copy-Item out/final/paper.tex out/_probe/proof_nn/paper.tex
Copy-Item out/final/tab_checks.tex out/_probe/proof_nn/ -ErrorAction SilentlyContinue

# 2) 只用 python 删掉 proof 环境（PowerShell 处理 LaTeX 转义不可靠）
$py -c "import io,re; p='out/_probe/proof_nn/paper.tex'; t=io.open(p,encoding='utf-8').read(); t=re.sub(r'\\\\begin\{proof\}.*?\\\\end\{proof\}','',t,flags=re.S); io.open(p,'w',encoding='utf-8',newline='').write(t)"
```

**关键**：**只删 `proof` 环境，保留 `proposition`。** 这样缺陷是「有命题无证明」这一类，不是「整节消失」。

### 判据

```powershell
& $py tools\quality_doors.py proof out/_probe/proof_nn
# 期望：FAIL，理由含「没有任何 proof 环境 —— 有命题没证明」
```

### 变异（证明这个样本测的是真门）

```powershell
# 把 check_proof 改成永远通过，重跑，期望 FAIL 变成 PASS
```

**若变异后仍报 FAIL** → 这个样本测的不是 `check_proof`，是别的东西 → **样本设计失败，重做**。

### 失败意味着什么

| 结果 | 含义 | 动作 |
|---|---|---|
| 删 proof 后仍报 OK | 门没在查 proof 环境 | 修门 |
| 变异后仍报 FAIL | 样本没走到门 | 检查是不是别处先报错了 |
| 都正确 | 这个门有了第一个独立样本 | **X 从 4 提到 5** |

## 实验 2：`iterlog` 门的构造样本

**要判的事**：迭代表里**没有「不信判据」**时，门会不会报错。

### 构造

**取 `out/final/paper.tex` 的迭代表**，把「不信」词换掉：

| 原词 | 换成 |
|---|---|
| `false positive` | `adjusted` |
| `was wrong` | `changed` |
| `looked like` | `appeared as` |
| `disagreed` | `differed` |

**保留「轮/现象/诊断/修正」四列表头，保留行数 ≥ 3。** 这样缺陷是「有表但没说为什么不信」。

### 判据

```powershell
& $py tools\quality_doors.py iterlog out/_probe/iterlog_nodoubt
# 期望：FAIL，理由含「没有任何「不信」判据词」
```

### 失败意味着什么

**这个实验比实验 1 更重要**，因为 `iterlog` 的判据是**我自己定的词表**（中英两套）。**如果换掉词就过不了，说明判据是「词表匹配」而不是「语义判断」**——**这本身就是 Threats 里要写的一条**。

| 结果 | 含义 |
|---|---|
| 换词后仍报 OK | 词表太宽（可能有别的词命中）→ 要收紧 |
| 换词后报 FAIL | 门工作，**但也证明它是词表匹配** → Threats 加一条 |

## 实验 3：逐层消融 C0–C3（补 v2 批判 5 的硬缺口）

**要判的事**：加一层是否带来「上一层抓不到的东西」。

### 四个条件

| 条件 | 跑哪些门 | 用哪些样本 |
|---|---|---|
| **C0** | 无 | 23 篇原始（基线） |
| **C1** | `numbers` | S_L2（实验 1 的产物）、S_L3（实验 2 的产物） |
| **C2** | `numbers` + `proof` | 同上 |
| **C3** | `numbers` + `proof` + `iterlog` | 同上 |

### 增量算法（这是 v3 定的，这里给具体表格）

| 样本 | C1 | C2 | C3 | 增量 |
|---|---|---|---|---|
| **S_L2**（有命题无证明） | ? | ? | ? | **增量(L2) = C2 检出 − C1 检出** |
| **S_L3**（有表无不信） | ? | ? | ? | **增量(L3) = C3 检出 − C2 检出** |

**期望**：

```
S_L2:  C1 漏 → C2 检出 → C3 检出      增量(L2) = 1
S_L3:  C1 漏 → C2 漏 → C3 检出        增量(L3) = 1
```

### 最容易出错的地方

**如果 C1 就检出了 S_L2**，说明 `numbers` 门因为别的原因报了错（如引用不存在）。**那增量就是 0，不是因为三层不重要，是因为样本不干净。**

**排查**：C1 报红时，先看它的**理由**是什么。如果理由是「未溯源的数字」，不是「缺证明」，那样本要重做（保证删 proof 后论文里没有新增未溯源数字）。

### 失败意味着什么

| 结果 | 含义 | 动作 |
|---|---|---|
| 增量(L2) = 0 | `proof` 门多余 | **三层塌成两层**，paper 改成「L1 + L3」 |
| 增量(L3) = 0 | `iterlog` 门多余 | 同上 |
| 两个都 = 1 | **三层成立** | 这是 Q2 论证的核心 |

## 实验 4：FActScore 的荒谬值测试

**要判的事**：现有事实性评测判「supported」时，是在看内容还是在看形状。

### 前提

**需要 LLM API key**（FActScore 用 LLM 拆原子事实）。本机没有 `openai`/`transformers`/`torch`，**跑不了**。

### 如果拿到 key

| 步 | 做什么 | 记录 |
|---|---|---|
| 1 | 拿一段含 `R^2=0.94` 的句子跑 FActScore | 判 supported / unsupported |
| 2 | **同一个句子，把 `0.94` 改成 `0.9999997`** | 判什么 |
| 3 | 再把 `0.94` 改成 `0.0000001` | 判什么 |

### 四种结果与含义

| 结果 | 含义 | 对我们的价值 |
|---|---|---|
| **都 unsupported** | 它不认计算值 | **立论成立**：混淆「事实错误」与「来源不同」 |
| **都 supported** | **它看形状不看内容** | **最强证据**：给出虚假可信信号 |
| 正常值 supported、荒谬值 unsupported | 它在读数值 | **立论输一半**：收窄到「无法被知识源支持的计算值」 |
| 都无判断 | 它自认覆盖不到 | **等于它替我们说了** |

### 如果永远拿不到 key

**退路**：**只做定义层面论证**，写成：

> FActScore 的判据是「这句是否被知识源支持」。**我们无法在本环境运行它（缺 LLM 依赖，实测）**，但它的判据定义**本身就排除了计算值**——因为知识源不包含「这个数是通过某次计算得到的」。

**这在 Q3 能过，Q2 过不了。** 必须在 Threats 里写明「这是定义层面的论证，不是实验层面的」。

## 实验 5：分类器漏检率（v3 第 6 点「最大的残余风险」）

**要判的事**：「形状像结构值的计算值」会被豁免多少。

### 构造（这一步要设计好，否则测不出东西）

从 `out/final/冻结数字.json` 的 818 条里，**挑出 30 个 value 是整数的计算值**（如 `724173`、`150`、`24`），然后**写成三种形式**：

| 形式 | 例子 | 会被判成 |
|---|---|---|
| 原样整数 | `724173` | `structural`（`abs > 1000` → `computed`，**这个还好**） |
| 加逗号 | `724,173` | **待测** |
| 科学计数 | `7.24173e5` | **待测** |
| 带单位 | `150 MWh` | **待测** |

### 判据

```powershell
& $py -c "import sys; sys.path.insert(0,'.'); import untraced; ..."
# 对每个变体跑 classify_token，记录它被判成什么
```

**漏检率** = 被判成 `structural`（豁免）的变体数 / 总变体数。

### 通过线（我建议的，不是定理）

| 漏检率 | 判断 |
|---|---|
| **< 10%** | 可接受，写进 Threats 作为「已知局限」 |
| **10–30%** | 要修分类器，或把结论限定到「带小数的计算值」 |
| **> 30%** | **核心判据不可靠**，论文要重构 |

### 失败意味着什么

**这一项是唯一可能推翻整篇论文的实验。** 如果漏检率 > 30%，说明「冻结表 + 精度感知相等」只覆盖了「带小数的计算值」，而整数计算值大量逃逸。

**那时论文要改成**：

> 我们的判据覆盖**带小数的计算值**（占 47.3% 里的 X%）。**整数计算值仍逃逸**，这是未解决的问题。

**这个版本仍然是诚实的论文，但贡献变小了。**

## 实验 6：A/B 扩到 5–10 个任务

**要判的事**：94 vs 90 是不是任务特异性。

### 成本核算（基于 R124 实测）

| 项 | 实测 |
|---|---|
| 插件臂 | **41.7 分钟**（其中 14 分钟在工具上） |
| 无插件臂 | **26 分 25 秒** |
| 一个任务两臂 | **约 70 分钟** |

**5 个任务 ≈ 6 小时；10 个任务 ≈ 12 小时。**

### 统计

| 项 | 做法 |
|---|---|
| 检验 | **Wilcoxon signed-rank**（配对，n=5 或 10） |
| 效应量 | 差值中位数 + bootstrap 95% CI（`tools/bootstrap_ci.py` 已有骨架） |
| 报告 | **不报 p 值单独存在**，必须带区间 |

### 失败意味着什么

| 结果 | 含义 |
|---|---|
| 分项方向一致（A 臂 L2 输、L3 赢）在每个任务都出现 | **三层叙事成立** |
| 方向不一致 | **三层是任务特异的**，论文只能说「在一类任务上」 |
| 总分差随机 | 4 分是噪声，**「插件更好」这句话不能说** |
