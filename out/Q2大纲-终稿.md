## 0. 一句话主张

**项目名：鉴真 / `veridical`**
> *A verification layer that knows where verification ends, and whether the record of it is real.*

> **一个 LLM 生成的报告是否可信，取决于四个互相独立的判据：数字可溯源、推导可证明、过程可审计、过程不发散。前三个是内容层，可以机械判；第四个是元层，判的不是内容对不对，是「继续做下去有没有意义」。我们给出四层的判据、实现和消融，并指出内容层到此为止——再往上一层的候选（假设是否合理、结论是否被证据支持）有不可验证性结果。**

**「鉴真」不是「验证」。** 验证问「对不对」，鉴真问「真不真」——后者包含「这份记录本身是不是编的」。

### 三个维度上的实测位置

| 维度 | A 臂（鉴真） | B 臂（无鉴真） | 判断 |
|---|---|---|---|
| **L1 数字可溯源** | **325/325** | 0（无冻结表） | **碾压** |
| **L2 推导可证明** | 1 命题 + 459 字符证明（**R124 补的**） | 1 命题 + 完整证明 | **追平** |
| **L3 过程可审计** | 6 轮迭代表 | 5 轮迭代表 | 略优 |

**三个维度全部不落后，其中一个碾压。**

**口径说明**：`325/325` 指 **A 臂的竞赛稿**（`aidc2026`，665 行）。本工具论文 `out/final` 自己是 **199/199**（全 token 口径；gate 只判小数 **43/43**）。两个数都对，但指的不是同一篇——混用会让审稿人算不清分母。

**但要说清时间**：R123 的 A/B 快照里，A 臂在 L2 上是 0 命题 0 证明（输 2 分）。`proof` 门是 7.4 小时后才加的。**「R124 之后 A 臂 Q2 会更高」是推断，不是实测**——重跑 A/B 是未完成的实验。

## 1. 定位：验证层，不是建模插件

| 层 | 内容 | 领域相关 |
|---|---|---|
| **判据层** | 四层判据 | 不相关 |
| **实现层** | 冻结表、精度感知相等、`proof` 门、`iterlog` 门、断路器 | 不相关 |
| **域配置层** | 哪些门启用、门槛值、`standard.json` | **相关** |

**证据**：35 道门里 **28 道不含数学建模特定关键词**（80%）。口径：按函数体里有无 MILP/regression/题型/聚类/灵敏度等词判，**粗判**，代码无关键词 ≠ 语义通用。

**代价**：说「通用」就必须在**至少两个域**验证。现在只有一个（数学建模，23 题）。**所以第二语料是硬要求，不是加分项。**

## 1b. 鉴真防什么、释放什么

### 三重目标

| 失败模式 | 表现 | 判据 |
|---|---|---|
| **逃避** | 说「这需要领域专家」；用「假设 X 成立」绕过不证；跳过某一小问 | `chk_prompt`（逐问必答）、`chk_proof`（必须有证明）、`chk_iterlog`（必须有不信判据） |
| **滥用** | 编数字；用可检查的等式代替证明；事后补迭代史 | `chk_numbers`（冻结表）、`chk_stamp`（判决绑定摘要）、`fence_mutation`（变异测试） |
| **浪费** | 同坑反复踩；页数调四次；检测器自错六次还在调参 | **L4（只有设计，无实现）** |

**覆盖度是不均的，必须自己说**：

| 目标 | 覆盖 | 证据 |
|---|---|---|
| 不滥用 | **强** | R121–R122 建的，35 门里大半在防编造 |
| 不逃避 | **中** | **R123–R124 才加的**三道门 |
| 不浪费 | **弱** | L4 一行代码没有 |

**这个演化史本身是论文的一节**：先做「防滥用」（数字不能编），两轮后才发现「防逃避」同样重要——因为一个数字全对、但把推导绕过不证的报告，同样不可信。

### 鉴真是释放，不是限制

**「验证」通常被读成约束**：门越多，模型越不敢动。**但鉴真的逻辑是反的**：

```
没有鉴真 → 模型写什么都心虚 → 倾向写模糊的话（"大致符合"、"可能"）
有鉴真   → 模型知道"我写的数能查" → 敢写具体的数
```

**A/B 是活对照**：

| | 敢写什么 |
|---|---|
| **A 臂（冻结表 818 条）** | `724173.37 元/日`、`Ea = 42.09 kJ/mol`、`95%CI [41.74, 42.45]` |
| **B 臂（无冻结表）** | 也写了具体的数，但**没有一条能机械核对** |

**A 臂不是被门限制住的，是被门托住的。** 论文原句：

> A verification layer is usually read as a constraint. We argue the opposite: it is what makes a specific claim possible. A model that knows a number can be traced writes that number with its decimal places; a model that does not writes "approximately".

### 「低成本」的正确算法：核对密度

**不是「时间少」，是「每一份投入转化成可核对的产出」。**

| | A 臂 | B 臂 |
|---|---|---|
| 生成时间 | 41.7 分钟 | 26.4 分钟 |
| 可机械核对 | **325 个** | **0 个** |
| 核对成本 | ~0（一条命令） | **人工核 200 个**（按 30 秒/个 **估** ≈ 100 分钟） |
| **总成本** | **~42 分钟** | **~126 分钟** |

**所以 A 臂的真实成本反而低 3 倍。**（`30 秒/个` 是估计，需实测 20 个计时验证。）

**「核对密度」的定义**：

```
核对密度 = 可核对的 claim 数 / 总投入
A 臂：325 / 41.7 = 7.8 个/分钟      B 臂：0 / 26.4 = 0
```

**B 臂不是「效率低」，是「核对密度为零」**——它的产出全都要人工介入才能验。

**而「低质量」的本质是**：

> 不是「产出少」，是「大量劳动花在了无法被核对的地方」。那部分劳动不等于零——它花了，但没人能验。

**所以动词是「转」不是「削」**：**把不可核对的劳动，转成可核对的产出**。B 臂的 200 个数不会因为「提纯」变少，它们会因为有冻结表而变成「可核对的 200 个」。

### 通用是结构性，不是枚举性

| | 枚举性 | **结构性** |
|---|---|---|
| 主张 | 「我在 N 个域验证过」 | **「我的判据不引用任何域概念」** |
| 反驳 | 「再加一个域」 | **「指出哪个判据依赖域」** |

**实测：35 门里 28 门不含建模关键词（80%）。** 判据层不引用域概念，所以「通用」是结构性主张。

**三层 claim 要分清**：

| Claim | 需要什么 | 现在有吗 |
|---|---|---|
| 判据不依赖**主题** | 主题各异的样本 | ✅ **23 个**（heat_sink / evaluation / prediction / network / queueing / population / clustering / multiobjective …） |
| 判据不依赖**格式** | 一个不同格式的样本 | ⚠️ **可自产**（一篇 IMRAD 报告，半天），但**只证适配、不证性能** |
| 真实文献上的**有效性** | Fontelo 的 60 篇 | ❌ 需 PUBMED XML |

**「所有用本架构输出的都可成为语料」——成立条件是「产出带冻结表」。** 不带表就不可核对，不是语料。

**但自产语料是循环**（用本架构写、再用本架构检），只能测格式适配，不能测真实缺陷分布。**这一条必须写进 Threats。**

### 检测 → 诊断 → 修复：一个完整闭环

**这不是「插件让人写得更好」，是插件发现了自己的缺陷：**

```
① R123 A/B 实测：A 臂 L1 强（325/325），L2 弱（27 对 29）
② 外部评审指出原因：「用可检查的等式替代了证明」
③ R124 加 proof 门（12:40:39，比 A/B 晚 7.4 小时）
④ 本论文自己写出命题 + 459 字符证明
⑤ 门现在报 OK：1 个命题、1 个证明、最短 459 字符
```

**这个闭环本身，是「鉴真能释放能力」的最佳证据**——它证明了机制能自己发现缺陷，并且修得动。

## 2. 四层结构

```
内容层 —— 产出对不对
├─ L1  值可溯源      对象：一个数     判据：在冻结表里吗         失败：数字是编的
├─ L2  推导可证明    对象：一条推理   判据：有非空证明吗         失败：有等式无证明
└─ L3  过程可审计    对象：一次迭代   判据：有不信判据吗         失败：事后复盘代替当下怀疑
        ↓
元层 —— 继续有没有意义
└─ L4  过程不发散    对象：一段轨道   判据：连续同错/编辑距离/上下文占比   失败：原地打转
```

**关键区分**：
- **L3 查「记录」**（事后可查）／**L4 查「当下轨道」**（实时可查）
- **L4 调「投入门槛」不调「质量门槛」**：降投入（早停、换法）✅／降质量（接受更差结果）❌

## 3. 四层独立性（三组证据）

| 证据 | 来源 | 证明了什么 |
|---|---|---|
| **A 臂：L1 高（325/325）、L2 低（0 命题 0 证明）** | A/B 实测（**R123 快照**） | L1 × L2 独立（正向） |
| **B 臂：L1 低（无冻结表）、L2 高（命题+证明）** | A/B 实测 | L1 × L2 独立（反向） |
| **本次会话：L3 高（HANDOFF+CHANGELOG+iterlog）、L4 低（同坑反复踩）** | 真实过程 | **L3 × L4 独立** |

**L3×L4 那条的原文**：

> 我记录了（HANDOFF、CHANGELOG、六轮迭代表），而记录里写的正是「我又踩了一次」。

### 类型独立 vs 实例独立（这一处我原来想错了）

原文写「还缺 L1×L4、L2×L4 的实例（构造 2 个样本）」。**那是把 L4 当成「第四层」在处理，错了。**

**三层的对象是「产出的属性」，L4 的对象是「过程的属性」**：

| | 对象 | 何时可查 |
|---|---|---|
| L1 / L2 / L3 | 静态产出（数字、证明、记录） | **事后**，读文件即可 |
| **L4** | **运行轨迹（失败次数、编辑距离、上下文占比）** | **只能实时观测** |

**所以 L4 与前三层的独立性是「类型的独立」，不是「实例的独立」**：

- 问「一张照片的颜色和它的拍摄时间独立吗」——不需要找实例，它们本来就是不同属性
- 问「L1 和 L4 独立吗」——同理，一个查数、一个查轨道，对象不重叠

**但要注意一个区别**：**逻辑上可分离 ≠ 实用上可观测**。

**能不能观测到「L1 高 L4 低」取决于有没有实时信号**——而那正是 L4 要设计的东西。

**所以正确的表述是**：

> **L1×L4、L2×L4 不需要构造样本证明独立性（对象类型不同）。需要做的是「让 L4 可观测」——也就是实现它的信号（同错计数、编辑距离、上下文占比）。**

**这比「构造两个样本」更准，而且它解释了为什么 L4 是元层：元层不是「更上一层的内容」，是「另一个维度」。**

## 3b. 这一处修正对论文的意义

**如果按错了的版本写（构造 L1×L4 样本），审稿人会问**：

> 「你构造的这两个样本，和 L1 有什么关系？L4 判的是过程，你怎么用静态样本证明它？」

**答不上来。**

**按修正后的版本写**，答案是：

> **L4 与前三层的独立性是结构性的（对象不同），不需要实例；需要的是「可观测性」的实现。**

**这就是「元层」这个词的准确含义**——不是「第 4 层」，是「另一个坐标轴」。

## 5. 为什么不能再加一层（上界）

| 候选第四层（内容层） | 为什么不行 |
|---|---|
| 假设是否合理 | 要领域知识，只能查「有没有声明」，不能查「对不对」 |
| 结论是否被证据支持 | **有不可能性结果**：*A Theory of Black-Box Tests*（arXiv:2006.10387） |
| 数据是否真实 | 只能查内部一致，不能查真实性 |
| 审稿人是否独立 | 只能查「有没有读别的报告」 |

**所以内容层到三层为止；元层另有一层，对象不同。**

## 7. Abstract（定稿版）

> Large language models write technical reports whose arithmetic is usually correct and whose numbers have no path back to anything computed. Existing factuality evaluations ask whether a sentence is supported by a knowledge source. **We measured 9{,}337 numbers across 23 technical reports and found that 47.3\% of them are computed values, which a knowledge source cannot support by construction; the upper bound of knowledge-source coverage is 35.1\%.**
>
> We build and evaluate a criterion for that missing half: a frozen table plus **precision-aware equality**, in which a written value is accepted only if it rounds from the frozen one at the number of decimals the paper wrote. We prove the rounding equivalence that justifies it, and show two failure modes of the naive alternatives.
>
> Removing the table drops the traced fraction from 81.7--94.9\% to 10.4--12.2\% on the five ablated problems. A sealed A/B comparison shows 94 against 90, but the dimensions move in opposite directions: **the tool arm loses points on derivation and gains them on process**, which is why we report four independent criteria rather than one.
>
> We report the boundary: the classifier is a shape rule; **of 35 checks we implemented, six have been validated by constructed defects and mutation testing**, the rest are listed in the appendix and are **not** used as evidence.

**每一句都能追到一个文件或一次运行。**

## 10. 必须写进 Threats 的九条

| # | 局限 |
|---|---|
| 1 | **分类器是形状规则**：形状像结构值的计算值会被豁免（**未量化，是最大残余风险**） |
| 2 | **单语料**：23 题全数学建模，别的域计算值可能只有 5% |
| 3 | **n = 1 的 A/B**：4 分差在单评分者的噪声内 |
| 4 | **两臂同底座模型**：Knight-Leveson 1986 —— 不独立，A/B 只当案例 |
| 5 | **L3 抓不到伪造的迭代史**：L3 只查「有没有记录」，不查「记录是否真实」 |
| 6 | **35 项里只有 6 项经证**：其余 29 项是判据实现，无独立样本 |
| 7 | **A/B 是 R123 的快照**：`proof` 门比它晚 7.4 小时。「R124 之后 A 臂 Q2 会更高」是推断，重跑 A/B 未做 |
| 8 | **自产语料是循环**：用本架构写、再用本架构检，只能测格式适配，不能测真实缺陷分布 |
| 9 | **人工核 30 秒/个 是估计**：核对密度那笔账里最不确定的数，需实测 20 个计时 |
| 7 | **消融只做了 5 题**（不是 23 题）：表 `tab:ablation` 的 81.7–94.9% → 10.4–12.2% 是那 5 题上的均值区间，其余 18 题没做消融 |

**第 5、6 条是这篇论文最诚实的地方，也是它区别于「35 项全绿」类论文的地方。**
