# 论文里的数字分几类（第 124 轮实测）

> 用途：给「现有 LLM 事实性评测覆盖不了计算值」这个主张提供**可跑的量化证据**，
> 而不是论证。数据由 `python tools/numeric_genre.py` 生成，口径见下。

---

## 为什么测这个

现有的事实性评测（FActScore、HaluEval、RAGAS）问的是：

> **这句话是否被知识源支持？**

那么一个前置问题必须先回答：

> **一篇技术报告里的数字，有多少能被知识源支持？**

如果只有一半，那「查知识源」这个判据就覆盖不了另一半 —— 这是**结构性的**，不是某个工具的缺陷。

---

## 方法

| 项 | 做法 |
|---|---|
| 语料 | `runs.json` 的 **23 题**（不扫 `out/runs/*` —— 实测只有 22 个目录，漏 1 题） |
| 抽取 | 去掉 `\code{}` 参数与 LaTeX 环境，按 `untraced` 的口径抽数字 token |
| **分类** | **用冻结表**：值在 `冻结数字.json` 的 `items[].value` 里 → `computed`；有小数但不在表里 → `config`；≤1000 的整数 → `structural`；1900–2100 的 4 位整数 → `time` |
| 覆盖 | **23/23 题都有冻结表**（`out/final` 有 818 条） |

**为什么用冻结表而不是正则**：正则分不清 `0.85`（假设的折现率）和 `0.847192`（算出来的）。冻结表是「这个数被算过一次」的直接证据。

---

## 结果

```
论文 23 篇，数字 9337 个

computed     4415   47.3%     ← 在冻结表里
config       2532   27.1%     ← 有小数但不在表里
structural   1643   17.6%
time          747    8.0%
```

### 三个可用的数

1. **47.3% 的计算值** —— 这类数字**在知识源里不存在**。不是「不支持」，是「本来就不该在那儿」。
2. **27.1% 的 config 值** —— 混合体：一部分来自题面/规范（知识源**可能有**，如「40 元/kW·月」），一部分是内部假设（知识源**没有**，如折现率）。
3. **25.6% 是结构值 + 时间** —— 这类不需要溯源，也不该被判「无依据」。

### 所以

> **知识源能覆盖的上界是 27.1%（config 全部算能查）+ 8.0%（时间）= 35.1%。**
> **剩下 64.9% 是计算值与结构值，前者的正确性判据只能是「它被算过一次」，不是「它被文献支持」。**

**这是「需要一个计算谱系判据」的量化依据，不是修辞。**

## 局限（必须一起说）

| 局限 | 说明 |
|---|---|
| **单语料** | 23 题全是数学建模论文。**别的领域计算值占比可能低得多**（如综述类论文以引用为主） |
| **`config` 是粗类** | 「假设值」与「引用值」混在一起，没有细分。要细分需要读上下文（如「假设折现率 8%」） |
| **冻结表由本工具生成** | 若作者手工编冻结表，`computed` 的边界会变。这是**共同设计**的残余风险，与论文第 8 节一致 |
| **没跑真 FActScore** | 本环境无 `openai` / `transformers` / `torch`（Python 3.12，实测），FActScore 依赖 LLM 拆原子事实，**跑不了**。所以本文只测「占比」，不测「FActScore 的具体判定」 |

**最后一条要说清**：**「跑不了」不是「它不行」**。要证明 FActScore 在计算值上失效，必须在有 LLM 的环境里真跑一次。本报告只做到「前置事实」这一步。
