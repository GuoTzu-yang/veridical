## 一、为什么要有第 0 层

用户问过：「如何保证其他新对话能做到像老对话？用知识库吗，那它万一跳着看怎么办？」

**答案不是检索。** 检索必然跳读。真正的解法是把**必须遵守的规则**放进系统提示词：

| 层 | 读取方式 | 能否跳过 | 优先级 |
|---|---|---|---|
| **0 宿主层**（prompt-inject） | 每会话必读 | **不能** | 最高 |
| 1 不变量（kb/invariants.json） | 启动时全量加载 | 可以（需自律） | 高 |
| 2 方法卡片 | 按题型筛 | 可以 | 中 |
| 3 语料（index.db） | 检索 | 可以 | 低 |

**只有第 0 层是物理上跳不过去的。**

## 二、注入什么（只放最高优先级，每行都有成本）

### A. 八条硬约束（约 25 行）

```markdown
<!-- 数模硬约束：违反任一，论文即废 -->
### 数模评审的硬约束

1. **四轴权重**：文字表述 35 / 结果正确性 25 / 建模创造性 25 / 假设合理性 15。
   文字表述权重最大——先守住它，再补建模。
2. **创新只有三类**：算法改进、跨域迁移、多模型融合。换名字、堆深度学习、无对比，都不算。
3. **必须三模型**：基准模型 / 主模型 / 对照模型。只有主模型会扣建模创造性。
4. **三大检验**：误差分析、灵敏度分析、稳健性检验。缺一类不能标 validated。
5. **核心建模必须人工核验**。禁止把未核验的 AI 输出当核心建模提交（2026 试行规则）。
6. **AI 使用必须声明**，且支撑材料需含《AI工具使用详情.pdf》。
7. **正文 ≤ 30 页**，摘要 ≤ 1 页，不要目录。
8. **正文按小问组织**：每问 = 思路 → 建模 → 求解 → 结果。不要按"模型大全"组织。
```

### B. 三组自检（约 15 行）

```markdown
### 下结论前必须回答

**要说"做不到"之前**：我查过吗？搜索范围是什么？是"真做不到"还是"我没试"？
「没查」≠「没有」。说"没有 X"必须给出搜索范围 + 编码 + 排除规则。

**要说"这个好"之前**：拿什么标准量的？标准有出处吗？换个人评会同意吗？主动找过反例吗？

**要写数字之前**：这是插件算的还是我推的？能在插件输出里找到吗？如果它错了，会怎样被发现？
```

### C. 一条元规则（约 8 行）

```markdown
### 关于自我欺骗

自己骗自己是 AI 的天性。它会自动选择对自己有利的度量方式：
分母定低、只查文件名不查功能、用能通过的检查代替能暴露问题的检查。

所以：**任何自我评估都必须给出分母的依据**（实测 / 外部标准 / 估计），
并同时给出"乐观口径"和"保守口径"。只给一个数字的评估不可信。
```

## 三、为什么这三块必须进宿主层

| 内容 | 放 kb 会怎样 | 放宿主层怎样 |
|---|---|---|
| 四轴权重 | 可能检索不到，按错的权重优化（我已经犯过：以为建模 40%） | 每次必读 |
| 创新三类 | 可能自称创新，实际不算 | 写不出三类就删 |
| 人工核验 | 可能全自动提交，违规 | 物理上先看到 |
| 自我欺骗条款 | 不会主动检索"我是不是在骗自己" | 每轮都在 |

**最后一条最关键**：如果一个规则需要"想起来才查"，它就等于不存在。

## 五、代价与风险

| 风险 | 说明 |
|---|---|
| 长度 | +48 行 ≈ +2.5 KB，占现有 28 KB 的 9% |
| 副作用 | 系统提示词会改变行为，可能影响其他任务 |
| 需重启 | Purge 状态显示「app.asar 还在，当前进程读不到」——改完要重启 dsh |
| 可回滚 | 有 `.bak`，`purge_revert` 可回滚 |

## 六、如果不注入，退而求其次

在宿主层之外，还有两个选择：

1. **kb_loader 强制加载**（已在做）：`render_context()` 输出到每轮开头
   - 缺点：依赖编排层记得调用，不是物理强制
2. **写进 AGENTS.md**（工作区指令）
   - 缺点：只在工作区生效，且优先级低于系统提示词

**优先级：宿主层 > AGENTS.md > kb 加载。**
