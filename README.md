# veridical ｜ 鉴真

**一个会拒绝的系统**
给 LLM 辅助科研用的验证护栏、它四轮转折的实测记录、以及一份把「举证责任」说清楚的系统性回顾

---

## 这是什么

三个仓库分工不同

| 仓库 | 内容 |
|---|---|
| **`veridical`**（本仓库） | 护栏本体，23 个子命令的能力层、35 道门禁、六环飞轮、以及全部规矩 |
| **`veridical-survey`** | 那篇 32 页的系统性回顾，《一个会拒绝的系统》 |
| `aidc2026` | 被护栏生产出来的赛题论文、代码、数据与结果 |

## 一句话主张

**报「拦住了 N/M」不构成任何证据**

样本可以被作者挑选、期望可以被作者设定、判定可以被作者实现
前两条在一个作者、一个语料的前提下无法根除，第三条必须根除

可接受的证据只有一种
**构造一个缺陷样本、调用真实的护栏、然后把护栏改坏，确认样本随之从「拦住」变成「漏检」**

我们实现并运行了这套变异测试，当前结果是 **假测试 0/4**

## 它拒绝什么

| 层 | 对象 | 判据 |
|---|---|---|
| L1 | 一个数 | 在冻结表里吗 |
| L2 | 一条推理 | 有非空证明吗 |
| L3 | 一次迭代 | 有「不信判据」吗 |
| L4 | 一段轨道 | 连续同错、编辑距离、上下文占比（**未实现**） |

前三层是内容层，第四层是元层，不是「更上一层的内容」，是另一个坐标轴

## 现在是什么状态

**诚实地说，门禁覆盖率只有 4/35**

35 道门里，只有 `numbers`、`figures`、`redteam`、`stamp` 四道同时具备构造缺陷样本与变异敏感
其余 31 道有判据代码，但没有任何构造缺陷证明它抓得住

加一道门的成本是十分钟，造一个能骗过它的样本的成本是三十到六十分钟
成本不对称，所以门的增长速度必然快于证据的增长速度
**这不是懒惰，是结构**

## 已知缺陷（不藏）

- **零 baseline 对比**
- **A/B 对照只有 n=1**
- **L4 一行代码没有**
- **31 道门没有检出能力证据**
- **未知缺陷的检出率不可知**

## 怎么用

```powershell
$env:PYTHONIOENCODING="utf-8"; $env:PYTHONUTF8="1"
python mmkit.py advise --data X.xlsx
python verify.py out/runs/X/paper.tex
python gate.py out/runs/X
python tools/verify_all.py
```

**不要用 `mmkit.py run` 一条龙**
那是自动模式，会替你做完所有建模决定，产出的是模板论文
